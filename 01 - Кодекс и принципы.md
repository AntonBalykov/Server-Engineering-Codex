# Кодекс и принципы

## Обязательные правила

1. Не удалять ресурс, пока не установлены его назначение, владелец и зависимости.
2. Не выполнять разрушительные команды без оценки последствий.
3. Не менять production без плана, проверки и возможности восстановления.
4. Не хранить секреты в Git, образах контейнеров, логах и открытых документах.
5. Не считать факт создания backup доказательством возможности восстановления.
6. Не открывать порт без установленной необходимости и владельца.
7. Не оставлять критичные сервисы без мониторинга и уведомлений.
8. Не использовать плавающие версии образов и зависимостей в production без осознанного решения.
9. Фиксировать важные изменения и результаты проверок.
10. Удалять только ресурсы, принадлежность которых подтверждена.
11. Применять принцип минимальных привилегий.
12. Для каждого критичного сервиса иметь понятную процедуру восстановления.

## Уровни требований

- **MUST** — обязательное требование.
- **SHOULD** — настоятельная рекомендация; отклонение нужно обосновать.
- **MAY** — применяется по ситуации.
- **N/A** — неприменимо; указать причину.

## Критерии готовности production

Сервер нельзя считать готовым только потому, что приложение открывается. Должны быть проверены безопасность, доступ, данные, резервирование, мониторинг, документация и сценарий восстановления.

## Принцип безопасной работы

- Сначала инвентаризация, затем действия.
- Сначала проверка команды и области воздействия, затем запуск.
- Предпочитать обратимые изменения.
- Для потенциально разрушительных действий использовать dry-run, если он поддерживается.
- Не выполнять массовую очистку Docker, файловой системы или БД без инвентаризации.
- Не копировать секреты и персональные данные в отчёты.
