# Безопасность

## Учётные записи и привилегии

- [ ] У каждого администратора персональная учётная запись.
- [ ] Нет общих административных аккаунтов без обоснования.
- [ ] Принцип минимальных привилегий соблюдается.
- [ ] Проверены группы `sudo`, `docker` и другие привилегированные группы.
- [ ] Отозваны доступы у бывших сотрудников и подрядчиков.
- [ ] SSH authorized_keys проверены и имеют владельцев.
- [ ] Секреты хранятся в менеджере секретов или защищённом хранилище.

> [!warning] Docker
> Членство в группе `docker` фактически предоставляет привилегии, близкие к root. Выдавай его только доверенным администраторам.

## SSH

- [ ] Используются SSH-ключи подходящего типа и длины.
- [ ] Root login отключён.
- [ ] Парольная аутентификация отключена после проверки ключевого доступа и аварийного сценария.
- [ ] Ограничены пользователи/группы, которым разрешён SSH-доступ, если это возможно.
- [ ] Проверены права `~/.ssh` и `authorized_keys`.
- [ ] Проверены логи успешных и неуспешных входов.
- [ ] Изменения SSH проверяются через `sshd -t` до reload/restart.
- [ ] Существующая сессия не закрывается до проверки новой.

## Firewall и службы

- [ ] Входящие соединения ограничены.
- [ ] Открытые порты соответствуют реестру сервисов.
- [ ] Нет ненужных слушающих служб.
- [ ] Административные интерфейсы не опубликованы в интернет без необходимости.
- [ ] Доступ к БД и внутренним API ограничен доверенными сетями.
- [ ] Проверены правила облачного firewall/security groups, если применимо.

## Обновления и уязвимости

- [ ] Определена политика обновления ОС и пакетов.
- [ ] Критические уязвимости оцениваются без неоправданной задержки.
- [ ] Перед обновлением критичного сервиса есть план отката.
- [ ] Проверяется статус перезагрузки после обновлений ядра/библиотек.
- [ ] Контейнерные образы и зависимости регулярно обновляются и проверяются.

## Проверка

- [ ] Проверены `ss -tulpn`, firewall и список системных служб.
- [ ] Проверены последние SSH-события.
- [ ] Проверен Fail2ban или эквивалент.
- [ ] Проверены права конфигураций и секретов.
- [ ] Результаты аудита зафиксированы.

## Инцидент

При подозрении на компрометацию: сохранить логи и доказательства, ограничить воздействие, отозвать/ротировать секреты с безопасного устройства, определить масштаб, восстановить доверенное состояние. Не стирать следы и не переустанавливать систему до фиксации необходимой информации.
